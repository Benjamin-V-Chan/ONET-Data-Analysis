# data-science-onet

## Overview

data-science-onet is the analytics, interpretation, and intelligence layer built on top of the O*NET ingestion pipeline. Once raw occupational data has been collected and normalized by ONET-Data-Collector, this repository takes over to inspect, validate, analyze, and structure that data into signals that are more useful for recommendation systems, career matching workflows, clustering-based exploration, and AI-powered guidance tools.

If the collector repository is the part of the stack that makes O*NET data usable, this repository is the part that makes O*NET data interpretable and operationally valuable.

The goal is not merely to produce charts. The goal is to transform structured occupation records into recommendation-ready intelligence. That includes understanding feature coverage, inspecting occupational similarity, engineering text-driven representations, validating schema consistency, generating occupation groupings, and surfacing patterns that can support downstream retrieval, ranking, and explainable AI workflows.

This public version of the repository contains the base architecture for the officially contracted project. This is not the full project as the full contents are privately contracted out.

---

## Why This Repository Exists

Even after O*NET data is collected and flattened, there is still a major gap between “structured dataset” and “intelligent system.”

A machine-readable table alone does not answer questions like:
- Which occupations are similar in meaningful ways?
- Which features separate one role category from another?
- Which keywords carry strong occupational signal?
- Which parts of the dataset are clean enough to rely on for ranking or retrieval?
- How can occupations be grouped into interpretable clusters for student exploration?
- How should structured role profiles be packaged for recommendation or LLM retrieval workflows?

This repository exists to answer those questions.

It converts normalized occupational data into higher-level signals that make the broader system more useful, more explainable, and more AI-ready.

## Core System Role

This repository is the **analytics and intelligence layer** of the broader O*NET career intelligence pipeline.

Its primary responsibilities are:

1. **Validate and inspect structured O*NET outputs**
   - confirm schema integrity
   - assess coverage and consistency
   - identify column-level or export-level irregularities

2. **Analyze occupational structure**
   - study how roles differ across skills, descriptors, and text fields
   - compare occupations based on structured and text-derived features
   - identify emerging patterns in role space

3. **Generate recommendation-oriented signals**
   - produce similarity-aware representations
   - create cluster-based exploration views
   - quantify keyword relationships to occupational features
   - support search and matching logic

4. **Prepare the data for AI consumption**
   - create more interpretable occupational representations
   - support retrieval, ranking, and prompt-grounding workflows
   - improve explainability for downstream AI systems

## Technical Scope

The repository is built around a downstream data science workflow operating on canonical O*NET artifacts generated by the collector repository.

### 1. Data Quality and Schema Validation
Before any modeling-style analysis is performed, the repository checks the integrity of the incoming data.

This includes tasks such as:
- validating required fields
- handling schema name variation across exports
- checking for missingness and inconsistent formatting
- inspecting column-level distributions
- measuring keyword-to-occupation coverage
- ensuring that downstream analyses operate on stable inputs

This stage is important because AI systems are highly sensitive to silent data inconsistency. A retrieval or recommendation pipeline built on unstable occupational features will often fail in subtle ways. This repository reduces that risk by explicitly validating the structured outputs first.

### 2. Exploratory Data Analysis
The next layer is systematic exploratory analysis of the occupational dataset.

This analysis is used to understand:
- how occupation families are distributed
- which fields are dense vs sparse
- which descriptors appear to carry the most signal
- how occupational roles vary in their text and structured representations
- where the dataset supports strong downstream use cases versus weak ones

The purpose of the EDA is not purely descriptive. It helps determine what kinds of signals are reliable enough to support recommendation logic, search ranking, clustering, or explanation.

### 3. Text-Based Feature Engineering
A major part of turning occupations into AI-usable entities is representing them numerically or semantically.

This repository supports modeling-style feature engineering over occupational text fields such as:
- occupation titles
- descriptions
- task language
- skills and knowledge descriptors
- other relevant text-heavy fields depending on the export structure

A common approach here is TF-IDF-based vectorization, which converts text into weighted feature representations that emphasize terms that are informative rather than merely frequent. These text-derived representations allow the system to move from raw string fields toward analyzable occupational embeddings or approximation layers suitable for similarity analysis and cluster formation.

While these are not frontier-model embeddings in the strictest sense, they are a crucial interpretable intermediate representation and a strong baseline for downstream semantic or hybrid AI workflows.

### 4. Representation Analysis and Dimensionality Reduction
High-dimensional occupational feature spaces are difficult to inspect directly. The repository therefore uses modeling-oriented reduction steps to compress representations while retaining useful structure.

Techniques such as TruncatedSVD can be applied to sparse text representations to produce lower-dimensional role embeddings that:
- preserve meaningful variation
- make occupation similarity easier to visualize
- improve clustering stability
- create more interpretable navigational views of career space

This is especially useful in student-facing exploration systems because raw occupational taxonomies can be overwhelming, while cluster-aware reduced representations make navigation more intuitive.

### 5. Occupation Clustering
Once role representations are created, the repository can group occupations into clusters using unsupervised techniques such as KMeans or similar methods.

The purpose of clustering here is practical, not academic. It helps convert thousands of granular occupational records into interpretable higher-level groupings that can support:
- student exploration flows
- recommendation diversification
- search faceting
- category-aware retrieval
- role neighborhood analysis

For example, cluster outputs can be labeled into navigation-friendly groupings like software/data, health services, design/media, education/social impact, construction/trades, operations/logistics, and other interpretable role families. These clusters become a second organizational layer beyond the raw O*NET hierarchy.

### 6. Keyword-to-Feature Attribution
Another high-value analysis supported by this repository is keyword attribution.

In a practical career guidance system, it is not enough to know that a keyword returns a set of jobs. It is also useful to understand what that keyword maps to in occupational feature space. This repository therefore supports workflows that measure how keywords align with descriptions, tasks, skills, knowledge areas, and other structured fields.

This is valuable because it creates more explainable systems. Instead of saying “this job matched your query,” a downstream product can say “this role matched because your query aligned strongly with these recurring skill, knowledge, and task descriptors.”

That kind of feature attribution is particularly useful for:
- explainable recommendations
- student-facing interpretation
- debugging matching logic
- prompt-grounding for AI assistants
- hybrid symbolic + LLM pipelines

## AI / LLM / Frontier-System Relevance

This repository is highly relevant to modern AI systems because frontier models are strongest when grounded in well-structured external context.

The analyses and outputs produced here can support:
- **LLM-backed career assistants** that need compact, structured occupational context instead of noisy web text
- **RAG pipelines** where occupations are retrieved as normalized role profiles
- **search and matching engines** that combine symbolic fields with text-derived role representations
- **explainable recommendation systems** where cluster position, keyword alignment, and structured descriptors all contribute to the recommendation rationale
- **agentic education workflows** that need occupation entities, similarity structure, and interpretable metadata for reasoning or decision support
- **future embedding-based systems** where the structured and text-engineered role representations here serve as a baseline or augmentation layer

A key advantage of this repository is that it does not rely solely on opaque black-box modeling. It creates interpretable intermediate structure first. That makes the overall system more debuggable, more explainable, and easier to operationalize in real education products.

## End-to-End Role in the Larger Pipeline

This repository assumes that ONET-Data-Collector has already produced normalized occupational data. It then performs the downstream intelligence work required to turn that normalized data into something closer to product infrastructure.

The full system therefore works like this:

1. Collect raw O*NET occupational data
2. Preserve raw source records
3. Flatten and normalize into structured datasets
4. Validate schema and coverage
5. Analyze occupational structure
6. Engineer representations over text and features
7. Group occupations into interpretable clusters
8. Attribute keywords back to meaningful occupational signals
9. Produce recommendation-ready and AI-ready artifacts for downstream systems

That full flow is what turns public labor-market data into a genuine career intelligence stack.
